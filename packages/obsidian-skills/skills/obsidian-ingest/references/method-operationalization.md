# Method operationalization

Use this reference when creating or substantially rebuilding a 02 `method`.

## Build before prose

Create one row per source-supported action: `task | trigger | input object | exact check | decision | named output | source block | gap`. Keep source actions concrete. If the source names fields, documents, people, versions, states or comparisons, retain them; do not collapse them into “check the information”.

Separate source content from operating design. E rows record only what the source explicitly says or visibly shows. D rows may add a work sheet, an order of operations, a record, configurable parameters, or a human review gate. A D row must say what the user or company still chooses and must not invent an effect, threshold, role, or legal conclusion.

## Write for the executor

Put the execution surface before evidence detail: goal and boundary, required inputs, named output, steps, decisions, pause/stop conditions, then a copyable template. The template must expose task-specific fields, source or comparison object, allowed state, difference handling, configurable confirmer, and handoff destination.

Use a scenario route or method fragment when evidence has useful actions but cannot support a full repeatable task. Do not turn a broad process map, FAQ list, or a single case into a method merely to increase card count.

## Multi-method gate

When one source yields multiple task methods, select the task with the most meaningful decision branches as a sample. Write it fully and run a desensitized scenario that fills the actual output, including one normal path and one pause or exception. If the user has not accepted the shape, pause before drafting siblings. Do not reuse a generic four-row work table, scenario text, flow, or pause prose across different named outputs.

## Paper dry run

A paper dry run contains a bounded synthetic or source case, the method version, a copied-and-filled output artifact, a normal path, a task-specific pause or exception, and friction that changes the next draft. It proves only that the method can produce an artifact. It never changes evidence-family count, applied-validation count, maturity, or external compliance status.
