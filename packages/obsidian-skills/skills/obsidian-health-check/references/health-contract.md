# Health-check contract

Use flat frontmatter. Required list fields are inline lists. Do not normalize optional legacy metadata unless the correction is deterministic.

The canonical audit emits `report_contract: obsidian-health-v1`, flat `findings` (`severity`, `category`, `file`, `reason`, `details`), retained grouped arrays for compatibility, and a summary split into current blockers, legacy debt, manual review, and information. It audits 00 processing records and referenced inputs, fully audits 01/02 contracts and all `project_reference` notes under `03_Topics/项目/**`, checks existing 04/05/06/90 rules, validates 98 templates separately, and checks only referenced 99 attachments. Exclude `.obsidian`, Git, cache, and backup directories.

A `project_reference` requires `status`, `created`, `updated`, `asset_scope`, `sensitivity`, `evidence_status`, inline-list `aliases`, inline-list `codex_project_labels`, inline-list `workstreams`, literal-boolean `daily_report_enabled`, and `migration_batch`.

An `action` is a persistent personal-Vault task card under `05_Review/Actions/`. It requires its immutable `action_id`, lifecycle `action_state`, area, dates, scope/sensitivity/evidence fields, inline project/workstream/source/evidence lists, next action, completion standard, carryover count, closure fields, and migration batch. IDs use `ACT-YYYYMMDD-NNN` and prefix the filename. Optional `start_on` and `due_on` encode a planned delivery window; when both exist, the start date cannot be later than the due date. Open states (`ready`, `in_progress`, `waiting`, `backlog`, `review`) require `status: active`; closed states (`done`, `cancelled`) require `status: archived`. Ready/in-progress actions need a scheduled date, waiting actions need a review date, and closed actions need a closure date and reason; `done` also needs completion evidence. Daily and weekly v3/v2 Plan/Report notes use inline `action_items` links that resolve to action cards. Between consecutive daily v3 Plans, a prior task may leave the next plan only after an explicit waiting/backlog/review/done/cancelled transition; a carried ready/in-progress task must be rescheduled and have a positive carryover count.

A collaborator role card is a `type: topic` note with `topic_kind: collaborator_reference`. It requires the normal scope/sensitivity/evidence dates plus inline `aliases`, `relationship_roles`, `projects`, `collaboration_topics`, `source_notes`, and `source_threads`. Its status is `active`, `review`, `archived`, or `ignored`; it needs at least one relationship role and at least one project or collaboration topic. The audit never infers missing people data.

Report metrics are optional for legacy reports. When present, `metrics_as_of` must be a real ISO date and each `metric_*` value must be a non-negative integer; a blank metric means uncollected rather than zero. The audit validates available workbench templates for action delivery dates, collaborator role-card fields, and the frozen metric fields on Daily, Weekly, and Monthly Report templates.

For v4 notes, a navigation source must be `navigation-index-v1 / index / index_only / false`. A semantic source needs the input manifest, coverage appendix, source-input existence and SHA-256 match, plus coverage, semantic and visual gates. Above ten inputs, its `source-input-manifest-v1` sidecar points back to the reader, shares its combined hash, declares the exact count, and carries the input, coverage and visual tables. A slide-photo learning sidecar classifies every image as `transcribed`, `duplicate`, `excluded`, or `unreadable`, names a valid duplicate representative, uses specific visible-content transcription, and resolves to real reader anchors and attachments. Reader destinations accept legacy `^c-*` anchors and precise `^t-*` anchors; a `^t-*` visual has one matching embed before its explanation, and duplicates cannot be embedded. Full PDFs require passed fidelity, `page-element-v1`, `page-region-v2`, one record per physical page, concrete content units and matching page counts. A learning source declares `topic-argument-v1`, its primary speaker, both learning gates and acceptance. Meeting coverage uses continuous exact time ranges. A mixed source cannot mark visual review not applicable. An active method needs verified v4 sources, `direct-content-v4`, `evidence-bound-method-v4`, exact evidence-family counts, operational sections and a matching dry run.

The method audit requires one direct-evidence ledger (`E` IDs), one compiler-design ledger (`D` IDs), execution rows with known E/D references and at least one explicit-action E reference, a decision table, a complete/pause-or-stop table, and a non-empty copyable template. A D row must use only `artifact`, `sequencing`, `recordkeeping`, `parameterization`, or `review_gate`, and must state its purpose, user choice, and non-claim boundary. A `case` is valid outside the active method tree with `operational_readiness: not_applicable`; it must not carry a method contract. Do not add v2 fields to legacy notes merely to create whole-Vault noise.

For knowledge cards, `02_Knowledge/方法/...` is the active-method tree and `02_Knowledge/归档/...` is the retained archive tree. Report an archived card in the active-method tree or an active card in the archive tree; do not move or delete it automatically.

Wiki targets resolve in this order: exact Vault-relative path, then one unique suffix path. Multiple candidates are ambiguous; no candidate is broken. Repeated filenames are informational unless an unqualified short Wiki link makes them ambiguous.

Default mode is report-only. Only an explicit `repair` or `apply` request may repair data that can be derived unambiguously from current Vault content. Otherwise surface a review need and preserve the original record.

Use `--fail-on error` for an acceptance gate: exit `1` reports in-scope findings and exit `2` means the audit could not run. `--focus-file`, `--path-prefix`, `--note-type`, and `--contract-version` narrow a report; a scope that selects no auditable note returns `2` unless `--allow-empty-scope` is explicit. `obsidian-health-v1` keeps `scope` as its legacy description string and adds `scope_details` for filters and selected files. JSON is the machine contract; `--format text` is a concise human report.

Markdown symlinks and resolved paths outside the Vault are never read. They produce an `external_symlink_note` fatal finding; dependency and build directories are excluded from discovery.
