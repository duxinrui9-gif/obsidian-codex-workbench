# 日报系统说明

## 系统职责

日报系统保存每天真实发生的推进、等待与下一步。它不替代项目文件、聊天工具或外部业务系统。

## 数据流

1. 每件可执行工作建立一张任务卡，放在 `05_Review/Actions`。
2. Daily Plan 只从已有任务卡安排当天动作。
3. Daily Report 只记录当天实际发生的结果、报告、等待与结转。
4. Weekly/Monthly Report 只汇总对应周期内可汇总的 Daily Report。

## 状态规则

| 状态 | 含义 | 必须补充 |
| --- | --- | --- |
| `ready` | 可以开始 | 下一动作与完成标准 |
| `in_progress` | 正在推进 | 最近活动日期 |
| `waiting` | 等待外部输入 | 复查日期 |
| `backlog` | 尚未排期 | 保留原因 |
| `review` | 待用户判断 | 需确认问题 |
| `done` | 已完成 | 完成证据 |
| `cancelled` | 用户明确终止 | 关闭原因 |

## 证据规则

- `[已核验]` 只能来自用户确认、可回读交付物或明确验证结果。
- `[已报告]` 是尚未独立核验的助手或工具报告。
- `[待验证]` 进入等待、风险或待确认区，不计入完成项。
- 没有核验证据时，写“无可核验输入”，而不是补造完成事项。

## 手动运行

- 只有用户明确要求时才创建或更新日报、规划、周报和月报。
- 不设置任何自动日程、文件监听或外部连接。
- 用户允许使用其 Codex 任务时，只保存最小成果摘要，不保存完整对话或身份标识。
