# Obsidian Starter Vault working rules

## Scope and safety

- Read `00_知识库配置.md`, `00_首页.md`, and the explicitly relevant project pages before acting.
- Process only material, questions, and task records explicitly named by the user. Do not scan an entire Inbox, external folders, chat history, accounts, or cloud services by default.
- Preserve originals in `00_Inbox`. A batch card records scope and status only; it is never evidence.
- Never store credentials, tokens, cookies, private keys, authentication configuration, contacts, or absolute local paths.
- All work is manual and on demand. Do not create schedules, watchers, catch-up jobs, mail, publish, or external writes.

## Knowledge chain

- `00_Inbox` holds explicitly selected raw inputs of any modality.
- `01_Sources` holds independently readable direct content. An index, a digest, a sidecar, or a partial source can navigate but cannot support new knowledge.
- `02_Knowledge` is built only from verified complete direct content. Keep facts, speaker claims, compiler inference, and unknowns distinct.
- A runnable method needs an E/D evidence ledger, inputs, outputs, decisions, stop conditions, template, and same-version dry run. A dry run never raises maturity.
- Project pages are readable project evidence; do not edit project facts unless the user explicitly asks.

## Daily operation

- The operational chain is `action card → Daily Plan → Daily Report → Weekly/Monthly Report`.
- A Plan schedules work and is never completion evidence. A Report describes actual work and may enter rollups only when `include_in_rollup: true`.
- Every planned action must end as done, waiting, carried over, deferred, or cancelled. Waiting requires `review_on`.
- First use: confirm the user's time zone, role, project categories, active projects, default sensitivity, and evidence boundary. Only after confirmation create real projects or action cards.
